# Rust Server Monitor Bot

Telegram-бот для мониторинга серверов Rust через BattleMetrics API. Бот отслеживает изменения на серверах и отправляет уведомления пользователям согласно настроенным фильтрам.

## 🚀 Основные возможности

### Мониторинг серверов
- ✅ Автоматическое отслеживание изменений на серверах Rust
- ✅ Фоновый процесс обновления данных каждые 5 секунд для активных пользователей
- ✅ Адаптивная система проверки (автоматически адаптируется к наличию активных пользователей)
- ✅ Первичная загрузка всех серверов и игроков при первом запуске

### Гибкая система фильтров
Бот поддерживает раздельное управление фильтрами для разных типов данных:

#### 👤 Фильтры игроков
- Имя игрока (уведомления при изменении)
- Приватность профиля (уведомления при изменении)

#### 🖥️ Фильтры серверов
- Минимум игроков (числовое значение или -1 для отключения)
- Максимум игроков (числовое значение или -1 для отключения)
- Статус сервера (вкл/выкл уведомления)
- Приватный сервер (вкл/выкл уведомления)
- IP/Порт (вкл/выкл уведомления)
- Обновление (вкл/выкл уведомления)

#### 🦀 Rust-специфичные фильтры
- Очередь игроков (минимальное значение или -1 для отключения)
- Вайп (вкл/выкл уведомления о вайпах)
- PVE режим (вкл/выкл уведомления)
- URL (вкл/выкл уведомления об изменении URL)
- Карта URL (вкл/выкл уведомления)
- Миниатюра карты (вкл/выкл уведомления)

### Добавление серверов
Множественные способы добавления серверов для мониторинга:
- **По ID** - введите ID сервера с сайта BattleMetrics.com
- **По названию** - поиск по частичному совпадению названия
- **Из списка** - выбор из общего списка доступных серверов с пагинацией

### Дополнительные функции
- ✅ Интуитивный интерфейс с удобным меню и навигацией
- ✅ Система отчетов - отправка сообщений разработчикам с логами ошибок
- ✅ Оптимизированная работа с БД - очередь запросов, кэширование профилей
- ✅ Валидация данных при заполнении БД
- ✅ Возобновление загрузки данных после сбоев
- ✅ Уведомления администратора о критических ошибках

## 🔧 Установка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd Rust_server
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

**Основные зависимости:**
- `aiogram==3.22.0` - фреймворк для Telegram ботов
- `aiohttp<=3.13` - асинхронные HTTP запросы
- `PyMySQL==1.1.2` - драйвер для MySQL
- `python-dotenv==1.2.1` - загрузка переменных окружения

### 3. Настройка базы данных

Создайте базу данных MySQL и выполните SQL скрипт:

```bash
mysql -u root -p < create_db_v3.sql
```

**Важно**: Используйте `create_db_v3.sql` - это последняя версия схемы БД с оптимизированной структурой.

Альтернативные способы импорта:
- MySQL Workbench: File → Run SQL Script
- phpMyAdmin: Import → Выберите файл `create_db_v3.sql`

### 4. Настройка переменных окружения

#### Автоматическая генерация шаблона

Используйте скрипт для генерации шаблона `.env`:

```bash
python sandbox/generate_env.py
```

#### Ручное создание файла `.env`

Создайте файл `.env` в корне проекта:

```env
# Telegram Bot
T_API_KEY=your_telegram_bot_token

# BattleMetrics API
BM_API_KEY=your_battlemetrics_api_key

# Database Configuration
DB_HOST=localhost
DB_PORT=3306
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_NAME=bm_db

# Admin ID (опционально, для уведомлений)
ADMIN_ID=your_telegram_user_id
```

**Где получить ключи:**

1. **Telegram Bot Token**:
   - Откройте [@BotFather](https://t.me/BotFather) в Telegram
   - Отправьте команду `/newbot`
   - Следуйте инструкциям для создания бота
   - Скопируйте полученный токен

2. **BattleMetrics API Key**:
   - Зарегистрируйтесь на [battlemetrics.com](https://www.battlemetrics.com)
   - Перейдите в [Developers](https://www.battlemetrics.com/developers)
   - Создайте новый API ключ
   - Скопируйте ключ в `.env`

3. **ADMIN_ID** (опционально):
   - Откройте [@userinfobot](https://t.me/userinfobot) в Telegram
   - Скопируйте ваш ID

### 5. Проверка подключения к БД

Перед запуском бота рекомендуется проверить подключение:

```bash
python test_db_connection.py
```

Если подключение успешно, вы увидите сообщение об успешном подключении.

## ⚙️ Настройка

### Изменение интервала проверки обновлений

В файле `battlemetrics_requests.py` в методе `update_info()` измените параметр `delay`:

```python
delay = 5  # Интервал проверки активных пользователей и данных (в секундах)
```

Процесс автоматически адаптируется:
- Если нет активных пользователей - ожидание с проверкой каждые 5 секунд
- Если нет данных для мониторинга - ожидание с проверкой каждые 5 секунд
- При появлении активных пользователей - обновление данных согласно их фильтрам

### TTL кэша профилей

В `repository.py` можно изменить время жизни кэша:

```python
self._instance._default_ttl = 3600  # 1 час (в секундах)
```

## 🎮 Запуск

### Запуск бота

```bash
python main.py
```

Бот выполнит следующие действия при запуске:

1. **Первичная загрузка данных** (только при первом запуске):
   - Загрузка всех серверов Rust из BattleMetrics
   - Загрузка всех игроков Rust из BattleMetrics
   - Заполнение базы данных

2. **Запуск фонового мониторинга**:
   - Проверка изменений каждые 5 секунд для активных пользователей
   - Автоматическая адаптация к изменениям в подписках

3. **Запуск Telegram бота**:
   - Обработка команд от пользователей
   - Отправка уведомлений согласно настроенным фильтрам

### Проверка работы

После запуска:
1. Откройте Telegram и найдите вашего бота
2. Отправьте команду `/start`
3. Вы должны увидеть приветственное сообщение и главное меню

### Основные компоненты

#### BattleMetricsController
Контроллер для фонового обновления информации о серверах и игроках. Автоматически запускается при старте бота и работает в фоновом режиме.

#### Dispatcher
Система обработки изменений с фильтрацией по пользовательским настройкам. Определяет, какие изменения должны быть отправлены пользователю.

#### Repository
Слой работы с БД (синглтон, очередь запросов, кэширование, валидация данных). Управляет всеми операциями с базой данных.

#### Profile
Класс пользователя с серверами, игроками и фильтрами. Хранит всю информацию о пользователе и его настройках.

#### Фильтры
- **RustFilter** - класс фильтров для серверов Rust (наследует базовые фильтры серверов)
- **PlayerFilter** - класс фильтров для отслеживания изменений игроков
- **ServerFilter** - базовый класс фильтров для серверов

## 🔍 Мониторинг и логирование

### Логирование в базу данных

Все действия и ошибки логируются в таблицу `logs` в базе данных. Для просмотра последних ошибок:

```sql
SELECT * FROM logs WHERE error_status = 1 ORDER BY log_date DESC LIMIT 10;
```

**Важно**: Используйте таблицу `logs` (не `logs_sql`). Структура была обновлена в версии 3.0.

### Периодическая статистика

Бот автоматически выводит статистику сервиса каждые 5 минут в логи. Статистика включает:
- Общее количество серверов
- Общее количество игроков
- Количество активных профилей
- Количество подписок на серверы
- Количество подписок на игроков

### Просмотр логов

Логи выводятся в консоль с различными уровнями:
- `INFO` - информационные сообщения
- `WARNING` - предупреждения
- `ERROR` - ошибки
- `CRITICAL` - критические ошибки

## 🐛 Решение проблем

### Бот не запускается

1. **Проверьте наличие всех переменных в `.env`**
   ```bash
   # Убедитесь, что файл .env существует и содержит все необходимые переменные
   cat .env
   ```

2. **Убедитесь, что база данных создана и доступна**
   ```bash
   python test_db_connection.py
   ```

3. **Проверьте версию Python**
   ```bash
   python --version  # Должно быть 3.8 или выше
   ```

### Ошибки подключения к API

1. **Проверьте правильность `BM_API_KEY`**
   - Убедитесь, что ключ скопирован полностью
   - Проверьте, что ключ активен на BattleMetrics

2. **Проверьте интернет-соединение**
   - Убедитесь, что сервер имеет доступ к интернету
   - Проверьте настройки файрвола

3. **Проверьте лимиты API**
   - BattleMetrics API имеет лимиты на количество запросов
   - При превышении лимитов запросы могут блокироваться

### Ошибки работы с БД

1. **Проверьте права пользователя БД**
   ```sql
   SHOW GRANTS FOR 'your_db_user'@'localhost';
   ```

2. **Убедитесь, что все таблицы созданы**
   ```sql
   SHOW TABLES;
   ```
   Должны присутствовать таблицы: `profiles`, `servers`, `players`, `rust_servers`, `logs`, и др.

3. **Проверьте логи в таблице `logs`**
   ```sql
   SELECT * FROM logs WHERE error_status = 1 ORDER BY log_date DESC LIMIT 20;
   ```

4. **Убедитесь, что используется правильная версия схемы БД (v3)**
   - Проверьте, что выполнен скрипт `create_db_v3.sql`

### Проблемы с первичной загрузкой данных

Если первичная загрузка данных прервалась:

1. **Проверьте состояние инициализации**
   - Бот автоматически сохраняет состояние при ошибках
   - При следующем запуске загрузка возобновится с места остановки

2. **Очистите состояние инициализации вручную** (если необходимо)
   ```sql
   DELETE FROM initialization_state WHERE admin_id = 'your_admin_id';
   ```

3. **Проверьте логи для деталей ошибки**
   - Ошибки первичной загрузки логируются с типом `servers_loading` или `players_loading`

## 📝 Разработка

### Добавление поддержки новых игр

1. Создайте новый класс сервера в `data_classes.py` (наследуется от `Server`)
2. Добавьте обработку в `ServerFactory.get_server()`
3. Создайте соответствующие фильтры в `filters.py`
4. Обновите схему БД при необходимости

### Добавление новых типов фильтров

1. Расширьте существующий класс фильтра (`RustFilter`, `PlayerFilter`) или создайте новый
2. Добавьте обработку в `dispatcher.py` в методе `_check_single_change()`
3. Обновите схему БД (таблицы `server_filters`, `player_filters`, `rust_servers_filters`)
4. Обновите методы в `repository.py` (`add_profile_filter`, `_load_server_filter`, `_load_player_filter`)
5. Добавьте UI элементы в `bot_handlers.py` (меню и обработчики callback)
